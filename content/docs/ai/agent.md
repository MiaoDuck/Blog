## 1. 推理模式 (Reasoning Patterns)

不同的推理模式决定了 Agent 解决问题的思维路径：

*   **CoT (Chain of Thought - 思维链)**
    *   **特点**：通过逐步拆解问题进行“脑内推理”。
    *   **局限**：缺少与外部环境的交互，若中间步骤出错容易导致最终结果跑偏（即“幻觉”）。
*   **ReAct (Reasoning and Acting - 推理与执行)**
    *   **特点**：将推理与行动结合。遵循“思考 -> 行动 -> 观察反馈 -> 再思考”的循环模式。
    *   **优势**：能根据外部反馈及时调整策略，容错率更高。
*   **Plan-and-Execute (计划与执行)**
    *   **特点**：先全局规划，生成明确的任务清单，然后再逐一执行这些步骤。
    *   **优势**：适合处理长线、复杂的任务，避免中途迷失方向。
*   **Reflection (反思机制)**
    *   **特点**：在执行后评估结果，记录错误并总结经验。
    *   **优势**：能够自我纠错并在多轮迭代中持续优化表现。

## 2. Coding Agent 的本质

Coding Agent 的底层逻辑本质上是一个 **LLM 循环 (LLM Loop)**。它通过不断接收代码上下文、生成代码或指令、获取执行结果并进行调整，从而完成复杂的软件工程任务。

## 3. 拥抱 AI Coding 时代

在 AI 辅助编程时代，核心竞争力不再是单纯的“手写代码”速度，而是**如何引导 AI 生成更高质量的代码**。

### 核心策略：
*   **上下文工程 (Context Engineering)**
    *   **定义问题**：清晰、准确地向 AI 描述需求和约束。
    *   **做决策**：在 AI 提供的多种方案中选择最优解。
    *   **验证结果**：建立完善的测试机制，确保 AI 输出的正确性。
*   **成本控制 (Cost Management)**
    *   **模型路由**：根据任务复杂度选择合适的模型（如简单任务用小模型，复杂推理用大模型）。
    *   **Prompt 优化**：精炼提示词，减少无效 Token 消耗。
    *   **缓存复用**：利用现有缓存避免重复计算。
    *   **任务评估**：权衡手动解决与 AI 解决的成本（如果手动一分钟能搞定，就没必要走复杂的 AI 流程）。

## 4. 工具使用的核心原则

Agent 在调用系统工具时，必须严格遵循**最小权限原则**与**防御性原则**，以确保系统安全和上下文的高效利用。

### 以命令行工具操作文件为例：

*   **读取文件：避免使用 `cat / head / tail`**
    *   **推荐替代**：使用专用的 `Read` 工具。
    *   **原因**：命令行读取容易造成全量内容返回，严重污染 LLM 上下文窗口；专用工具支持精细化读取（如指定行数和偏移量）。
*   **编辑文件：避免使用 `sed / awk`**
    *   **推荐替代**：使用专用的 `SearchReplace` 或 `Edit` 工具。
    *   **原因**：专用工具仅发送 Diff 差异，大幅节省 Token 并减少代码冲突，同时便于人类审查。注意：被替换的旧字符串 (old string) 必须在上下文中唯一匹配。
*   **写入文件：避免使用 `echo` 或重定向**
    *   **推荐替代**：使用专用的 `Write` 工具。
    *   **原因**：`echo` 往往无法感知原文件内容，容易导致误覆盖，且修改后难以追踪文件状态。
